# 09 · S1 规格冻结：本地宿主 / 邀请卡 / 操作日志 / 离线验签

> 状态：**M0 冻结版（v1.0）**，供实现方直接编码，供 arch 评审放行。
> 范围决策来自用户 2026-11-11 原话：**「可以支持最小的就行，最小化部署就是本机启动一个然后让其他 agent 来参会就可以了，同时可以支持服务器部署，要轻量化，不要占用太多的性能资源。」**
> 本文只冻结 **S1**。被推迟的项在 §9 明确列出，**不许实现方顺手多做**。
> 评审输入：`docs/team/05-decentralized-{pm,em,arch}-review.md`。本文每条都能追溯到那三份的条目号（A-x / B-y / C-z / R-n / W-n）。

---

## 0. S1 是什么（一句话）

> **一台机器上 `agchat room new` 起一个本地宿主，拿到一张邀请卡；把卡发给别人，别人的 agent 凭卡进场开会；会议结论可以离线重算。`agchatd` 一行不动，服务器部署照旧。**

三条硬边界：

| 边界 | S1 的答案 | 依据 |
|---|---|---|
| 传输 | **只有 `direct`（HTTP）**。loopback 默认，`--expose-lan` 才写内网地址进卡 | 用户"本机启动一个，其他 agent 来参会" |
| 部署 | 本地宿主 = 一个进程 + **一个** SQLite 文件；服务器部署 = 同一个二进制换 `--addr/--expose`，或继续用 `agchatd` | 用户"同时可以支持服务器部署" |
| 资源 | 常驻 **1 进程 / 1 库 / 1 ticker**；会议结束后日志是**唯一**增长物（每 op 一行 JSON）；不搞一房间一库 | 用户"轻量化，不要占太多性能资源" |

**不做**：公网中继、自动打洞、Web UI、短码、WebRTC、区块链。（§9 全量清单）

## 1. 名词与身份

| 名词 | 定义 | 出处 |
|---|---|---|
| **roomRef** | `base64url_no_pad(sha256(roomKeyPub))`，32B → 43 字符。**对外唯一身份**，取代 `roomId` 与会议号 | arch A-3 |
| **roomKey** | 一场会一把 Ed25519 密钥对。私钥只在宿主上，**永不进卡、永不进日志** | arch §2.2 |
| **hostKey** | 宿主进程级 Ed25519（跨会议），S1 只用于签 ack 与本地控制面；**不做 TOFU**（推迟） | arch A-6 降级 |
| **agentKey** | 参会 agent 自己生成的 Ed25519，落 `~/.agchat/seats/<roomRef>.key`；**座位靠它认回，不靠 alias** | arch A-18/A-19 |
| **alias** | 展示名，**永不作为授权依据** | arch A-18 |

**话术边界（必须原样出现在 SKILL 与 README）**：本方案没有 PKI。卡的签名只能证明"签发者持有 roomKey 私钥"，不能证明"签发者是某个人"；身份可信上限 = 你们交换这张卡的那个聊天窗口。

## 2. 邀请卡（分层卡）

### 2.1 人读块

```
[人读块 · 不是凭证，可改]
周岭 的 agent 邀你参加「月付定价」· 3 人 · 今天 18:00 前可进 · 本机/内网
[机读块 · 整段保留，剥掉多余字符再解码；改一个字就废]
---agchat-invite-begin---
agchat-invite:v1:<payload>.<sig>
---agchat-invite-end---
```

- 人读块 **≤ 500 字符**（pm R6）。**不做 URL**（IM 预览机器人会自动 GET，arch B-20）；**不做短码**（需要中心，§9）。
- 人读块与机读块交叉校验：人读块里的议题必须与 payload 的 `th`（topicHash）一致；不一致 → 篡改。

### 2.2 机读块格式

```
agchat-invite:v1:<base64url_no_pad(payload)>.<base64url_no_pad(sig64)>
```

- **验签顺序是硬规则**：`split(".")` → 对**收到的原始 payload 字节**验 `sig` → 通过后才 `json.Unmarshal`。
- 签名域：`"agchat-invite:v1" + 0x00 + payloadRaw`（防跨域复用：卡签名不能当 op 签名/信封签名用）。
- 剥字符规则：解码前删除所有非 base64url 字母表字符（`\r\n\t >&#x200b;` 全角空格等），**折行不影响内容**。
- **机读块单行 ≤ 1024 字符**；**不许**为了压长度删 `ids`/`seats`/`rv`（arch 打回条件 12）。

### 2.3 payload（短键，`omitempty`，禁止 null）

```jsonc
{
  "v":   1,                 // 卡格式版本；未知值 fail closed，不猜
  "api": 1,                 // 宿主接口版本；未知值 fail closed
  "ref": "43字符base64url",  // roomRef，必须 = sha256(key)
  "key": "43字符base64url",  // roomKeyPub
  "ids": ["iv_7f3a"],       // 本卡覆盖的 inviteId 全集（genesis 里已列全）
  "uses":3,                 // 本卡总座位数 = sum(ids 的 maxUses)
  "seats":3,                // 全场座位数（B 知道"还差谁"）
  "exp": 1765000000000,     // joinBy：毫秒；0 = 不过期。**只用于能否进场，与会议时长无关**
  "th":  "16字符hex",        // sha256(topic)[:8]；全量 topic 只在人读块
  "hn":  "周岭的MacBook",    // 宿主显示名（AC8 要"谁开的"）
  "on":  "周岭",             // owner 显示名
  "caps":["join","read","post","propose","vote"], // 闭合枚举，未知值 fail closed
  "rv":  {"res":1,"vote":1,"hash":1},             // 规则版本：结果 schema / 计票 / hash 域
  "ep":  [{"k":"loopback","u":"http://127.0.0.1:54321"}], // 可空；空 = 只能用 CLI 本地桥
  "n":   "16字符base64url"   // 卡 nonce，防同内容卡混淆
}
```

**卡里禁止出现**：密码、adminKey、roomKey 私钥、任何长期秘密（arch 打回条件 4）。

### 2.4 三类失败必须是三句不同的人话（pm R6 / arch B-19）

| 现象 | 技术判定 | 人话（原样使用） |
|---|---|---|
| 剥字符后切不出两段 / base64url 解码失败 / 长度不足 | 结构性失败 | **卡不完整**：转发时被截断了。请让对方把 begin/end 之间的整段重发一次。 |
| 能解码、字段齐全，但签名验不过 | 认证失败 | **卡对不上**：内容被改过，或不是这台主机的签发卡。不要用它。 |
| 验签通过但 `ref` 与当前会话不符 | 身份失败 | 这是**另一场会**的卡。 |

判定顺序必须是"先结构、再验签、最后比对身份"。

## 3. 宿主的 HTTP 接口（S1 全部路由）

宿主**不复用 `internal/api`**（em 条件 3：`api.Routes` 冻结 15 条；arch 禁止 `api → host`）。宿主自带一个最小 mux，全部挂在 `internal/host`。

公共规则：

- 默认只绑 `127.0.0.1`。`--expose-lan` 才绑 `0.0.0.0`，并把内网地址写进卡。
- **必须校验 `Host` 头**（只接受 `127.0.0.1:<port>` / `localhost:<port>` / `--expose-lan` 时的本机地址）。
- **不设 `access-control-allow-origin`**（arch A-24：否则浏览器里任意网页可读本机房间）。
- 无凭证端点**只读且不推进状态机**（arch R-7 / N10）。
- 限流默认全关（em §3 坑 1），避免 loopback 共用一个桶。

| 方法 | 路径 | 凭证 | 说明 |
|---|---|---|---|
| `POST` | `/v1/room` | 本地控制面 token | 建会，返回 `roomRef` / `seats` / `maxRounds` / `estimate` |
| `POST` | `/v1/invite` | 本地控制面 token | 发卡（`uses` 座位），返回卡文本 |
| `GET`  | `/v1/card/{ref}` | 本地控制面 token | 复看已有卡（`--card-file` 用） |
| `POST` | `/v1/join` | 卡 + agentPub + nonce | 进场；**原始卡是唯一凭证** |
| `GET`  | `/v1/next`  | agent token | 长轮询；`yourTurn` / 轮次 / 剩余预算 / 截止秒 |
| `POST` | `/v1/post` | agent token | 发言（`opKey` 必填） |
| `POST` | `/v1/propose` | agent token | 方案（`opKey` 必填） |
| `POST` | `/v1/vote` | agent token | 投票（`opKey` 必填） |
| `POST` | `/v1/summary` | agent token（仅获胜者） | 概述 |
| `GET`  | `/v1/result` | agent token | 结论 + `ownerReport` |
| `GET`  | `/v1/status` | 无（只读） | 人看的进展，**不推进状态** |
| `GET`  | `/healthz` | 无 | 存活 |

**能力校验只有一个入口**：`admit(card/seatCap, requestedCap) (ok bool, reason string)`（arch A-9）。S1 只有 direct 一条载体，但**仍然必须走 `admit()`**，否则 S2 接 envelope 时会分叉。

**join 幂等**：`joinKey = sha256(agentPub ‖ inviteId ‖ nonce)`；重复 `joinKey` 不重复扣 `uses`，返回同一座位（arch A-14）。

## 4. 操作日志（唯一证据）

每场会一个 `ops.jsonl`，**只追加**，一行一个 op。**轻量约束：不记录心跳**（见 §5）。

```jsonc
{ "i": 1,                       // 链内序号，从 1 开始
  "t": 1765000000123,           // 生效时刻 = 引擎当次 op 的 now（em 条件 1：op@now）
  "o": "post",                  // create|invite|join|post|propose|vote|summary|advance|end|reject
  "a": "m_2",                   // 作者座位（宿主 = "host"）
  "p": { ... },                 // op 载荷（规范化 JSON：键升序、无空格、无 null）
  "ph":"<sha256 hex>",          // 前一条的 hash；首条为 64 个 0
  "h": "<sha256 hex>",          // sha256("agchat-op:v1" + 0x00 + canonical{i,t,o,a,p,ph})
  "s": "<base64url sig64>"      // 作者对 h 域签名的原始字节签名
}
```

- `advance` 必须携带**判定输入**（arch R-3）：`{reason, deadlineHit, allVoted, votesSeenSet[], seatLastOpSeq[]}`。只记录"我决定跳轮"是不合格的。
- `reject` 记录**被拒绝**的 op 及错误码（arch 4.4：比成功的 op 更有证明力）。
- **`ack` 收据**：宿主对每条被接受的 op 用 `hostKey` 签 `{i, h, t}`，随响应返回，参与者存 `~/.agchat/seats/<ref>.receipts.jsonl`（arch C-4）。
- 崩溃一致性：**日志先行 + commit 标记**（arch R-4）。`ops.jsonl` 里可能有"签了但未生效"的尾巴，导出 bundle 时只取**已提交前缀**。

### 4.1 op 载荷 schema（**v1.1 冻结，三方共用，不许自造字段名**）

验签方要**只凭 op 流**重建转写稿算 `transcriptHash`，所以下列字段必须齐全（`?` = 可省略）：

```jsonc
create   : {ref,key,topic,seats,maxRounds,maxAgents,maxMinutes,maxOutput,tokenBudget,
            ids:[{id,uses,exp}],rv:{res,vote,hash},hn,on}
invite   : {id,uses,exp}
join     : {inviteId,agentPub,alias,ord,joinKey}
post     : {seq,round,agentId,alias,text,replyTo?,support?}      // ★ alias 必须进载荷（v1.1）
propose  : {id,seq,agentId,alias,title,body,supersedes?}
vote     : {agentId,alias,proposalId?,finalStance?,reason,redirectedFrom?}
summary  : {agentId,alias,text}
advance  : {reason,deadlineHit,allVoted,votesSeen:[agentId],seatLastOpSeq:{agentId:seq}}
end      : {snapshot:{state,round,emptyRounds,roundSkipped,endReason,convergenceReason,
                      winnerProposalId,phaseStartedAt,startedAt,endedAt,seq,planSkipped:[],
                      summaryText,summaryAuthor,summaryAt}}
reject   : {attemptedOp,code,message,detail?}
```

规则：
1. `topic` 的规范化**只有一个实现**：`invite.TopicHash(...)`；任何人都不许自己写一份 `normalize`。
2. `ops.jsonl` 的行结构见上面的 `Op`（`i/t/o/a/p/ph/h/s`），**载荷本身是规范化 JSON**（键升序、无空格、无 null）。
3. 验签方**不得**为了拿到 `alias`/`round`/`text` 而回查数据库或调用 `room` 的聚合——这是 B-13「重放不走 Create/Join」的直接要求。

## 5. 时间与掉线（S1 的确定性来源）

**S1 的唯一时序决定：本地宿主关闭 presence-abstain（arch R-2）。**

理由（同时满足三方）：

1. `presetAbstainForGone` 读 `LastSeenAt`（`engine.go:787-808`），而 `LastSeenAt` 由轮询到达时刻写入 —— **这个输入不在 op 流里**（arch N3 / em 条件 2）。要让重放可信，要么记录心跳（日志 3–10 倍，**违背用户的轻量要求**），要么关掉这条判定。
2. 关掉后，谁会弃权只由「投票窗口截止」这一条**可被记录的 `advance` op** 决定 → 重放可复算，日志保持每 op 一行。
3. 对用户是更好的产品行为：本机会议里"你 3 分钟没轮询就把你算弃权"是敌意设计。

**保留的墙钟**（S1 允许，因为有 `advance` op 记录）：
- `MaxMinutes`（默认 30）、`turnTimeout`（90s 跳轮）、`VotingWindow`（60s）。
- 每一次由时间引发的跃迁都必须写 `advance` op。**禁止"没人请求就不结算"和"任意匿名 GET 触发结算"两种极端**。

**`VotingWindow` 在 S1 保持 `const`**（arch R-1 推迟到 S2：只有异步档才需要它可配）。

## 6. 重放与验签（S1 = tier 1）

`agchat verify <bundle.zip>` 做**纯函数重放**（arch B-12 / B-13），三件事：

1. 逐条校验链：`ph` 与 `h` 与签名；断链/伪签 → `failed` 并报第几条。
2. 从 op 流重建 `{Room 终态, Agents, Messages, Proposals, Votes}`（**不调用 `Create`/`Join`/`Post`，不生成任何新 ID/token/时间戳**，不用 `e.now()`）。
3. 重新聚合两条指纹并比对：
   - `decisionHash`（现有，`result.go:1008`）——锚**结论**
   - `transcriptHash`（新增）——锚**过程**：`sha256(canonical[{seq,alias,round,text,replyTo,support}])`（**v1.3：加 `seq`**，否则 `reject` op 一插序号就漂，无从对齐）

输出三态（arch C-6/C-7）：

| 状态 | 含义 |
|---|---|
| `verified` | 结论一致 + 转写一致 + 全部签名有效 |
| `failed` | 任一不一致，**必须指出第几条 op / 哪个指纹** |
| `unverifiable` | 链路完整但缺 `ack` 收据 / 缺终态快照 / 规则版本不匹配 |

**话术禁令**（arch C-8，写进 SKILL 与 README）：禁止出现「不可篡改」「可证明公正」「宿主的每次排序都可重算」。允许：「发出后不可静默改写」「干预可枚举」「结论可复算」「参与者交互可留证」。

## 7. CLI（一个二进制 `agchat`）

```
agchat room new --topic T [--seats 3] [--rounds 6] [--minutes 30] [--addr 127.0.0.1:0] [--expose-lan] [--db PATH] [--json]
agchat room status [--ref REF] [--json]
agchat room close  --ref REF
agchat room resume --ref REF                      # ★ v1.1 增补：宿主停止后按同一 roomRef 拉起，结论指纹必须不变（AC4）
agchat invite  --ref REF [--uses 1] [--json]      # 打印分层卡
agchat join    --card FILE|TEXT [--as 名字] [--yes] [--json]   # 先报"谁开的/议什么/花多少"，--yes 才真进
agchat next    --ref REF [--wait 20] [--json]
agchat post    --ref REF --text T [--reply-to N]
agchat propose --ref REF --title T --body B
agchat vote    --ref REF (--proposal P | --abstain)
agchat result  --ref REF [--json]
agchat export  --ref REF [--out bundle.zip]
agchat verify  --bundle bundle.zip [--json]
```

> **v1.1 增补（Lead 裁决，验收需要机器可判定）**：
> 1. `room resume --ref` 是正式子命令（AC4 依赖它）；语义 = 复用已有状态、不重建房间、不新发卡。
> 2. `--json` 至少覆盖 `next` / `result` / `room status` / `verify`：输出单行 JSON 到 stdout，**人话只走 stderr**。
> 3. `join` 不带 `--yes` 时：必须打印同意门三行，**退出码 3**（"需确认，未进场"），不得静默成功——这样验收脚本能机器判定 pm P1。
> 4. `result --json` 必须含 `decisionHash`（`sha256:...`）与 `transcriptHash`，验收据此判"指纹不变"。

- 数据目录：`~/.agchat/`（可用 `AGCHAT_HOME` 覆盖）
  - `agchat.db`（**单库**，多场会共用，`tenant_id` 恒为 `local`）
  - `rooms/<ref>/host.json`（`{ref,pid,addr,startedAt,version}`，让下一个 agent 回合能找到宿主 —— arch B-17）
  - `rooms/<ref>/ops.jsonl`
  - `seats/<ref>.key` / `seats/<ref>.receipts.jsonl`
- **A 侧第一步就要说人话**：`room new` 打印「本机常驻，关掉终端不影响；重启电脑后需 `agchat room resume`」。

## 8. 不许破的东西

1. `agchatd` 行为不变：`api.Routes` 15 条不动；现有 HTTP 契约与状态码不动。
2. `internal/room` 不许出现 `host/invite/envelope/direct/tunnel/tenant` 任何标识符（arch B-7）；CI 加 grep 门禁。
3. 不新增任何 `require`（arch 打回条件 2）：Ed25519/SHA-256/ecdh 全在 stdlib。
4. `decisionHash` 的 payload 结构不许改（arch B-6）。
5. `alias` 不许作授权依据（arch A-18）；任何 `Close` 走 `roomKey`，不引入 `adminKey`（A-11）。
6. 现有 26 条隔离用例 + meeting 套件必须全绿（基线已存档 `.run/baseline-*.txt`）。
7. **默认资源占用**：空转时 CPU ≈ 0（ticker 1s，无长轮询时不做事）；单会 6 人 10 轮后 `ops.jsonl` ≤ 2 MB；RSS 目标 < 100 MB。

## 9. S1 明确不做（S2 候选，不许顺手做）

| 推迟项 | 为什么可以推迟 | 何时必须回来做 |
|---|---|---|
| `envelope` 异步信封（人肉搬运） | 用户明确要"最小"；直连已能覆盖"本机+内网" | 有跨 NAT 需求时 |
| `quorum`/`unconfirmed`/`unreachable_abstain` | 只在异步档才有意义 | 随 envelope |
| `VotingWindow` 可配（R-1） | 直连档 60s 合理 | 随 envelope |
| `revokeSeat`（踢已在场座位） | 需要新 op + 授权语义 | S2 第一批 |
| TOFU / `hostKey` 链 / 隧道档 | 都要额外密码学与传输 | S2 |
| tier 2 严格时序复算（`--strict`） | tier 1 已能给"结论一致/转写一致"的判决 | S2 |
| 一卡 N 座的分发 UI、短码、Web 页面、二维码 | 与"最小"冲突 | 视用户反馈 |

> **诚实边界（写进对外表达）**：S1 的"去中心化"准确含义是**去掉第三方服务器**，不是去掉宿主。**A 的机器关机/休眠 = 会议停摆**；这不是 bug，是单写入者形态的固有代价。

## 10. arch 准入门禁（v1.2，`docs/team/05-decentralized-arch-review.md` §3 的 G0–G16 落地版）

> 裁决：**GO-WITH-CONDITIONS**。以下每一条都写明"不做会破什么"。**不属于自己包里的条目不要做**。

### 10.1 卡 payload 的 7 处必改（`internal/invite`）

1. `ids` 的注释改为"**本卡覆盖的 inviteId 全集**"；删掉"genesis 里已列全"（建会后可继续发卡）。
2. **`uses` 必须自证**：`join` 时校验 `uses == Σ maxUses(ids)`，不符 → 拒绝（否则"A 偷偷多发卡"不可查）。
3. **`seats` 必须自证**：`join` 时校验 `seats == create.seats`。
4. **`rv` 不匹配的后果**：归第三类（"这是另一版规则办出来的会"），**不许**硬失败成"卡对不上"。
5. 新增 **`iat`**（签发时刻，毫秒）。
6. `ep.k` 枚举写全：`loopback` | `lan` | `tunnel`；**`k=="lan"` 必须带 `ins:1`**（明文入站标记）。
7. **人读块必须含 `ref` 的前 8 字符短指纹**（arch A-7：B 可以用第二个通道口头比对）。

### 10.2 `internal/oplog` 的 7 处必补

1. `type Seat struct{ Ref, InviteID, JoinKey, AgentPub, AgentID, TokenHash, Alias string; Ord int }` 与 `type SeatBinding` —— **三方共用，不许各自定义**。
2. **签名域 6 个，且不提供通用 `Sign()`**：只提供 `SignOp/SignAck/SignInvite/SignControl/...`，让"用错域"变成写不出来的错误。域前缀：`agchat-op:v1` / `agchat-ack:v1` / `agchat-invite:v1` / `agchat-control:v1`。`s` 字段**不参与 hash**。
3. **`Ack` 由 `roomKey` 签**（不是 hostKey），结构 `Ack{Ref string; I int; H string; T int64; S string}`。**S1 删除 `hostKey` 概念。**
4. `Manifest` 增加 `expect{decisionHash,transcriptHash}`、`opsVersion`、`bundleVersion`；并写明**verify 不许信任 `expect`**（只用它做差异定位）。
5. `TranscriptMsg` 增加 **`seq`**（`reject` op 一插，序号就漂；不锁 `seq` 无从对齐）。
6. reason code 枚举固定（`turn_timeout` / `round_idle` / `rounds_done` / `budget` / `time_limit` / `votes_complete` / `summary_done` / `summary_timeout` / `no_winner` / `admin_close` / `resume_clock_adjust`）。
7. `CanonicalJSON` **拒绝 float 与 null**（浮点在两次序列化间会变字节）。

### 10.3 G7（最大缺口）：座位绑定与"凭卡进场"怎么接到引擎上

`engine.Join` 的唯一鉴权是**房间密码**（`ops.go:256`），卡里没有密码。做法：

- 宿主 `engine.Create` 拿到的 `password` **只在宿主内存/私有文件里**，**不进卡、不进日志、不进 `ops.jsonl`**。
- 卡持有者 `join` 时，宿主用这个内部密码调 `engine.Join`，**但要顺便把 `alias` 由宿主强制唯一**（冲突加后缀），且**`alias` 永不作为授权依据**。
- reclaim：走 `engine.Do` 闭包做 token 轮换（参考 `ops.go:271-290` 的既有分支），**禁止宿主自己重算 `m_N`/`Ord`/`ModeratorID`**。
- 必须有一条 parity 测试：断言宿主 reclaim 后的终态与引擎 reclaim 分支一致。

### 10.4 G8 幂等（宿主自建表，不动 `op_keys`）

`join`/`post`/`propose`/`vote`/`summary` 全部幂等：宿主自建 `idem(ref, agentPub, kind, op_key)` 唯一表；`join` 用 `joinKey = sha256(agentPub‖inviteId‖nonce)`。**不许复用现有 `op_keys` 表**（键里没有 `kind`，`seq` 语义是消息序号）。

### 10.5 G9 `resume` 时钟修正（**不做则 AC4 必破**）

`MaxMinutes` 仍是墙钟（`engine.go:818-827`）：停机跨越 30 分钟 → 恢复瞬间会议终止 → `decisionSet.hash` 必变。
**做法**：恢复时把 Room 的全部绝对时间戳（`CreatedAt`/`BriefingDeadline`/`StartedAt`/`PhaseStartedAt`/`Plan.TurnStartedAt`）**整体后移停机时长**，并记一条 `advance{reason:"resume_clock_adjust", downtimeMs}`。

### 10.6 G10 advance-then-act + G12/G13 控制面

- 允许触发时间跃迁的**只有两条路径**：(a) 1s ticker；(b) 每个改状态请求之前。**两者都必须先写 `advance` 再 act。**
- **无凭证端点一律不 tick**，验收要有一条：匿名 `GET /healthz` 后 `ops.jsonl` 行数不变。
- `GET /v1/status` **改为需要本地控制面 token**（`--expose-lan` 下它是未认证的议题泄漏口）；`/healthz` 保持开放但**不含任何会议数据**。
- 控制面 token 存 `~/.agchat/control.token`（0600）。

### 10.7 G11 `--expose-lan` 四件套（S1 唯一承认的机密性缺口）

① 卡上 `k:"lan"` + `ins:1`；② `agchat invite` 打一次警告；③ SKILL v3 要求 agent 能把这句转述给主人（"你们的内网地址写在这张卡上，且是明文"）；④ §9 的诚实边界加一条"内网明文"。**验收主路径不使用该档。**

### 10.8 G14 / G15 两条静态门禁

- **G14**：`server/internal/room/**` 里读 `LastSeenAt` 的位置必须只剩 `notesFor`（`ops.go:578`）一处；出现第二处参与判定 → CI 红。前提是 R-2 关掉 presence-abstain 后 `LastSeenAt` 退化为纯展示字段。
- **G15**：`verify` 路径的源码里不得出现 `Create(` / `Join(` / `now()` / `crypto/rand`（用 `go/ast` 扫描，做成测试）；`verify` 输出必须带稳定 reason code。

  > **口径注脚（Lead 裁定）**：§10.2⑥ 的 11 个枚举是 **`advance`/`end` 的 reason**，不是 verify 判决码，两者不许混用。`verify` 自己一组判决码（`ok` / `chain_broken` / `op_hash_mismatch` / `sig_invalid` / `decision_mismatch` / `transcript_mismatch` / `ack_missing` / `ack_sig_invalid` / `snapshot_missing` / `manifest_version_mismatch` / `advance_reason_unknown` …），而 §10.2⑥ 的枚举用于**校验 `advance` op**，出现枚举外值 → `unverifiable/advance_reason_unknown`。
