**篡改实验（我自己动手改的，不是听汇报）**：

| 我改了什么 | verify 判决 | 证据 |
|---|---|---|
| 第 **120** 条 op（vote）的 `proposalId` 改成 `p_9` | `failed` / `op_hash_mismatch` | `failAt=120`，「第 120 条 op 的 h 与重算不符」 |
| 第 **7** 条 op（post）的 `text` 改成一句话 | `failed` / `op_hash_mismatch` | `failAt=7` |
| 用 PS 写入时引入 UTF-8 BOM，文件不可读 | `unverifiable` / `bundle_unreadable` | 「这属于结构性失败…无法据此判断会议结论」 |

第三行不是失败，是**设计生效**：结构性损坏与"被改过"必须分开报，否则用户会去怀疑发卡的人。

## 6. 已知边界（写给用户，不美化）

1. **A 的机器关机/休眠 = 会议停摆。** 这里的"去中心化"准确含义是**去掉第三方服务器**，不是去掉宿主。
2. **没有 PKI。** 卡只能证明"签发者持有同一把密钥"，不能证明"是谁"。身份可信上限 = 你们交换这张卡的那个聊天窗口。
3. **`--expose-lan` 是内网明文**（默认只绑 `127.0.0.1`）；卡上会标 `k:"lan"` + `ins:1`，验收主路径不使用该档。
4. **`verify` 只能证明"这条链发出去后没被静默改写"**，不能证明"链里记录了真实发生的一切"。唯一有对抗力的是参与者的 `ack` 收据。
5. **卡泄漏 = 一个座位 + 议题 + 宿主可探测性**（不是"全会"，但也不只是座位）。

## 7. 推迟到 S2 的项（等于本报告的"有条件"部分）

| 推迟项 | 为什么能推 | 何时必须回来 |
|---|---|---|
| `envelope` 异步信封（人肉搬运也能开会） | 用户明确要"最小"；直连覆盖本机/内网 | 有跨 NAT 需求时 |
| `quorum` / `unconfirmed` / `unreachable_abstain` | 只在异步档才有意义 | 随 envelope（一起做，否则破"不输出假共识"） |
